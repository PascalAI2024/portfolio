# Capability Map

The portfolio is organised by the problem being solved, not by a catalogue of
frameworks.

| Capability lane | What it demonstrates | Representative proof |
| --- | --- | --- |
| AI systems and agent operations | Governed tool use, durable knowledge, model routing, human review | JarvisMCP, project-memory systems, agent workflows |
| Product and platform engineering | Web, realtime, mobile, desktop, data, and workflow products | CRM, privacy automation, productivity and mobile systems |
| Infrastructure and recovery | Deployment, reliability, security remediation, and integration | Docker/VPS operations, WordPress recovery, dependency remediation |
| Interactive systems | Games, simulations, embedded devices, and product interaction | Game Studio, JarvisNano, interactive prototypes |
| Research and analytics | Better decisions from evidence, benchmarks, and data quality | Benchmarks, Kaggle work, SEO and trading analytics |

Every lane must link to a case study or public proof before it is expanded.
